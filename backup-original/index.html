CONCEPTS, MADE VISIBLE

Understand the mechanism

The core ideas behind TLB-based paging, in concise form.

01 / ADDRESSING
▦

Virtual address

The address generated by the CPU. Paging divides it into a virtual page number and an offset within that page.

VA = page × page size + offset
02 / MAPPING
▤

Page table

The operating system's mapping structure. A valid entry maps a virtual page to a physical frame; an invalid entry causes a page fault in this model.

Virtual page → frame
03 / FAST PATH
⌕

TLB hit

The requested page number is found in the TLB. The cached frame number is used without a page-table lookup.

TLB → frame → address
04 / SLOW PATH
⇢

TLB miss

The page is absent from the TLB. The page table is checked; if valid, the mapping is inserted into the TLB.

Miss → page table → TLB
05 / TRANSLATION
⌗

Page offset

The offset selects a byte within the page. Paging preserves it during translation because page size and frame size are equal.

PA = frame × page size + offset
06 / EVICTION
⟳

TLB replacement

When all TLB entries are occupied, FIFO evicts the oldest inserted entry; LRU evicts the least recently accessed entry.

Small cache · finite entries
