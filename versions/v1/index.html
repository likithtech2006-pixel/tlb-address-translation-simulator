    Field notes

    How the machine thinks

    01

    Splitting the address

    With page size 2n, the low n bits are the offset and the rest form the virtual page number (VPN). No arithmetic is required in hardware, only wiring.

    VPN = ⌊VA / S⌋ · offset = VA mod S
    02

    The TLB is a cache of PTEs

    A tiny associative memory keyed by (ASID, VPN). On a hit the frame number arrives in about a cycle; the page table is never touched.

    hit → PA = PFN · S + offset
    03

    Set associativity

    Low VPN bits select a set and the remaining bits are the tag. Direct-mapped TLBs are cheap but suffer conflict misses, which the bit view colours in amber.

    sets = entries ÷ ways · index = log₂ sets
    04

    Walking the table

    On a miss, a k-level page table costs k memory reads before the data read. This is why huge VA spaces depend so heavily on TLB reach.

    miss = t + k·m + m
    05

    Faults, dirt and shootdowns

    A non-present PTE traps to the OS. Under demand paging it picks a victim frame, writes it back if dirty, and invalidates the victim's stale TLB entry (a shootdown).

    EAT += p · S
    06

    Context switches

    Without ASIDs, every switch must flush the TLB. With ASID tags, entries from several processes coexist and survive the switch.

    match = (ASID, VPN)

    Impact

    Where this is useful

    Address translation happens billions of times a second inside every CPU, yet it is invisible. TLB/Scope makes it visible, measurable and testable. These are the people it helps, and how.

    Students & exam preparation

    Check hand calculations of VPN, offset, physical address and EAT in seconds. Typical university and GATE-style questions are solved step by step in the Calculation player, so you learn the method, not just the answer.

    • Every formula shown with real numbers
    • Hit / miss / fault paths side by side

    Teachers & classroom demos

    One-click scenarios (Belady's anomaly, thrashing, context switches, demand paging) project well on a screen. Rewind the timeline and ask “what if the TLB were bigger?”, and the whole run replays live.

    • Ten ready-made lessons
    • Shareable links reproduce a demo exactly

    Lab evaluation & viva

    The built-in self-test runs 96 automated checks in front of the examiner, including textbook results such as Belady's 9 → 10 misses and EAT = 130 ns. Export the log as CSV/JSON or print a PDF report.

    • Correctness you can demonstrate
    • Viva drill with 14 model answers

    Hardware design trade-offs

    CPU architects must choose TLB size, associativity and replacement policy under tight area and power budgets. The Policy lab plots hit ratio against size for six policies on the same trace, which is the kind of curve used to justify those choices.

    • Fully, set-associative and direct-mapped
    • OPT shows the best possible result

    Performance engineering

    Shows why programs with poor locality run slowly: each TLB miss costs a k-level page walk. The time ledger and EAT bars make the cost concrete, which is the reasoning behind techniques such as huge pages and cache-friendly data layouts.

    • Measured vs modelled access time
    • Locality, loops and strided workloads

    Operating systems & security

    Explore what kernels actually manage: ASID tags vs flushing on a context switch, TLB shootdowns after a mapping changes, write protection and dirty-page write-back. Flushing on every switch is the same cost trade-off kernels weigh when they isolate address spaces for security.

    • Up to 4 processes with ASIDs
    • Demand paging with FIFO / LRU / CLOCK
